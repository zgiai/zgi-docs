# 什么是 ZGI

ZGI 是一套开源 AI 产品栈。`zgi-pre` 是这套产品栈的顶层集成仓库，负责把后端、前端、沙箱、插件执行等独立服务组合成一个可以本地启动、联调和发布的整体。

简单说，`zgi-pre` 不是存放全部业务代码的“大仓库”，而是 ZGI 的集成入口。它管理启动流程、公共配置、本地开发脚本和跨仓库协作规则，让贡献者可以从一个地方拉起完整产品栈。

## 一句话定义

ZGI 是一套由多个独立服务组成的开源 AI 产品栈；`zgi-pre` 是它的顶层集成仓库，用来统一启动流程、共享基础设施，并明确各仓库之间的职责边界。

> ZGI 不追求把所有服务合并成一个庞大的仓库。它保留服务边界，同时提供一致的本地启动和集成体验。

## `zgi-pre` 负责什么

当前顶层仓库主要负责：

- Docker 启动和服务编排
- 本地开发辅助脚本
- 顶层仓库配置和 GitHub 工作流
- 多仓库的发布集成
- 对外说明文档和贡献者入口

## 哪些代码不在这里

核心服务代码仍然保留在各自仓库中，并通过 Git 子模块挂载到 `zgi-pre`：

- `api/`：后端服务
- `web/`：前端应用
- `sandbox/`：代码执行沙箱
- `plugin-runner/`：插件执行服务

因此，在 `zgi-pre` 中工作时，你通常是在处理产品集成层，而不是直接修改某个服务的业务实现。

## 为什么要这样组织

开源一个多服务 AI 产品时，常见问题通常集中在四个方面：

1. 服务代码分散在多个仓库，新贡献者不容易理解整体结构。
2. 本地启动步骤多，手工配置容易出错。
3. Docker 启动流程和源码开发流程容易脱节。
4. 贡献者不知道某个改动应该提交到哪个仓库。

`zgi-pre` 的作用，就是在不强行改成单仓库架构的前提下，把这些问题收敛到一个清晰的集成入口里。

## 这对你意味着什么

你在 `zgi-pre` 里通常会做这些事：

- 启动完整本地栈
- 调整顶层 Docker 编排
- 维护环境变量模板和同步逻辑
- 更新子模块指针
- 维护顶层文档和仓库协作配置

如果要修改具体服务的业务逻辑，通常应该先进入对应的服务仓库处理。
