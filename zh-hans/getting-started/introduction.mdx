# 什么是 ZGI

ZGI 是一套开源 AI 产品栈，而 `zgi-pre` 是它当前的顶层集成仓库。

`zgi-pre` 不是把所有业务代码都塞进来的“大仓库”。它更像一个 product shell，负责把多个独立服务组装成一套可启动、可联调、可发布的产品形态。

## 一句话定义

ZGI 是一个面向开源产品集成的顶层仓库，用来统一启动流程、共享基础设施和跨仓库协作方式。

> ZGI 的目标不是消灭服务边界，而是在保留独立服务仓库的前提下，提供一套一致的本地启动和集成体验。

## `zgi-pre` 负责什么

当前 root 仓库主要负责：

- Docker 启动与编排
- 本地开发辅助脚本
- 顶层仓库元信息与 GitHub 工作流
- 多仓库的发布集成
- README 与对外说明文档

## 哪些代码不在这里

核心服务代码仍然保留在各自仓库里，并作为 git submodule 挂到 `zgi-pre`：

- `api/`：后端服务
- `web/`：前端应用
- `sandbox/`：代码执行沙箱
- `plugin-runner/`：插件执行服务

所以当你在 `zgi-pre` 里工作时，更多是在处理“产品集成层”，而不是直接修改全部业务实现。

## 为什么要这样组织

开源一个多服务 AI 产品时，常见问题通常有四类：

1. 真正的代码分散在多个仓库里
2. 本地启动步骤太多，容易出错
3. Docker 流程和源码开发流程彼此割裂
4. 贡献者不知道某个改动应该落在哪个仓库

`zgi-pre` 存在的意义，就是在不强行改造成单仓 monorepo 的前提下，把这些问题收敛掉。

## 这对你意味着什么

你在 `zgi-pre` 里通常会做这些事：

- 启动完整本地栈
- 调整顶层 Docker 编排
- 维护 env bootstrap 和同步逻辑
- 更新 submodule 指针
- 维护顶层文档和仓库协作配置

如果是具体服务逻辑改动，通常还是先回到对应子仓库处理。
