# 系统架构

ZGI 采用多服务架构。`zgi-pre` 位于最外层，负责把后端、前端、沙箱、插件执行服务和共享基础设施组合成一套完整的本地产品环境。

## 架构分层

从上到下可以分为四层：

1. **产品入口层**：前端应用、接口入口、用户工作台。
2. **业务服务层**：后端接口、智能体编排、工作流、权限与成本管控。
3. **能力服务层**：知识库检索、模型网关、沙箱执行、插件执行。
4. **基础设施层**：PostgreSQL、Redis、向量数据库、对象存储和日志系统。

## 顶层仓库的职责

`zgi-pre` 不直接承载全部业务逻辑。它主要负责：

- 初始化和更新子模块
- 生成 Docker Compose 配置
- 管理本地启动脚本
- 协调整套产品栈的环境变量模板
- 统一说明各服务之间的连接方式

## 核心服务边界

- `api/`：负责后端接口、业务编排和数据访问。
- `web/`：负责前端页面、控制台和用户交互。
- `sandbox/`：负责隔离执行环境，承载代码运行、工具调用等高风险任务。
- `plugin-runner/`：负责插件执行和外部能力接入。

## 本地启动链路

执行 `make dev-docker` 后，顶层脚本会按顺序完成子模块检查、环境变量补齐、Compose 文件生成和服务启动。这样贡献者不需要手工记住每个服务的启动顺序。

## 设计原则

- **服务独立**：每个核心服务保留独立仓库和维护边界。
- **集成统一**：完整产品体验由 `zgi-pre` 统一启动和协调。
- **基础设施复用**：完整产品模式下共享 PostgreSQL、Redis 等基础设施。
- **本地优先**：贡献者应能在本地快速拉起接近生产形态的环境。
