# 快速开始

这份指南帮助你在本地启动 `zgi-pre`，并了解最常用的开发命令。完成这些步骤后，你应该可以拉起完整的 ZGI 本地产品栈。

## 前置要求

开始前请确保本机具备：

- Git
- Docker Desktop，或其他兼容的 Docker 运行环境
- Make

## 克隆仓库和子模块

推荐直接递归克隆：

```bash
git clone --recurse-submodules <repo-url>
cd zgi-pre
```

如果你之前已经克隆过仓库：

```bash
git submodule update --init --recursive
```

## 启动完整本地栈

推荐使用下面的命令启动：

```bash
make dev-docker
```

第一次运行时，顶层启动流程会自动完成这些工作：

- 初始化缺失的子模块
- 为各服务补齐缺失的环境变量模板
- 重新生成顶层 Docker Compose 文件
- 启动整套本地 Docker 栈

## 中国大陆网络构建模式

如果镜像构建经常因为网络问题变慢或失败，可以使用：

```bash
./dev/start-docker --china
```

这个模式会在当前构建中启用更适合中国大陆网络环境的镜像源配置，但不会改写仓库中受版本控制的模板文件。

## 常用辅助命令

只检查本地环境变量文件和模板之间的差异：

```bash
make env-check
```

只补齐缺失键，保留你已有值：

```bash
make env-sync
```

如果你想使用“源码开发 + 中间件容器化”的模式：

```bash
make setup
make dev-docker
make dev-api
make dev-web
```

## 默认本地访问地址

当前常用入口包括：

- 前端应用：`http://localhost:13000`
- 后端接口：`http://localhost:2678`
- Weaviate: `http://localhost:18080`
- 代码执行沙箱：`http://localhost:18194`
- 插件执行服务：`http://localhost:15000`

如果端口和本机已有服务冲突，可以修改 `docker/.env` 中对应的宿主机端口。

## 共享基础设施模型

在完整 `zgi-pre` 产品栈里：

- PostgreSQL 由整套产品栈共享
- Redis 由整套产品栈共享
- 代码执行沙箱在完整产品模式下复用共享的 PostgreSQL 和 Redis，不再单独启动一套实例

这样做的目标是：在保留单服务独立启动能力的同时，避免完整本地栈里重复起太多基础设施。

## 什么时候要回到子仓库

`zgi-pre` 负责组装和启动整套产品栈。

如果你要改具体服务行为，通常应该回到对应仓库：

- 后端逻辑改 `api/`
- 前端改 `web/`
- 沙箱运行逻辑改 `sandbox/`
- 插件执行逻辑改 `plugin-runner/`

如果改了子仓库，常见流程是：

1. 先在子仓库提交
2. 再回到 `zgi-pre` 提交更新后的子模块指针
