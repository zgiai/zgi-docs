# 快速开始

这份指南帮助你快速拉起当前的 `zgi-pre` 本地环境。

## 前置要求

开始前请确保本机具备：

- Git
- Docker Desktop 或兼容的 Docker 运行环境
- Make

## 用 submodule 一起克隆

推荐直接递归克隆：

```bash
git clone --recurse-submodules <repo-url>
cd zgi-pre
```

如果你之前已经克隆过仓库：

```bash
git submodule update --init --recursive
```

## 启动完整本地栈

推荐入口是：

```bash
make dev-docker
```

第一次运行时，root 层的 bootstrap 流程会自动完成：

- 初始化缺失的 submodule
- 给各服务补齐缺失的 env 模板
- 重新生成 root compose 文件
- 启动整套本地 Docker 栈

## 中国大陆网络构建模式

如果镜像构建经常因为网络问题变慢或失败，可以使用：

```bash
./dev/start-docker --china
```

这个模式会在当前构建里启用更友好的镜像源配置，但不会改写仓库里受版本控制的模板文件。

## 常用辅助命令

只检查本地 env 和模板之间的差异：

```bash
make env-check
```

只补齐缺失键，保留你已有值：

```bash
make env-sync
```

如果你想走“源码开发 + 中间件 Docker”模式：

```bash
make setup
make dev-docker
make dev-api
make dev-web
```

## 默认本地访问地址

当前常用入口包括：

- Web: `http://localhost:13000`
- API: `http://localhost:2678`
- Weaviate: `http://localhost:18080`
- Sandbox: `http://localhost:18194`
- Plugin Runner: `http://localhost:15000`

如果端口和本机已有服务冲突，可以修改 `docker/.env` 中对应的宿主机端口。

## 共享基础设施模型

在完整 `zgi-pre` 产品栈里：

- `postgres` 是共享的
- `redis` 是共享的
- `sandbox` 在 product mode 下复用 shared Postgres / Redis，而不是再起一套独立实例

这样做的目标是：在保留单服务独立启动能力的同时，避免完整本地栈里重复起太多基础设施。

## 什么时候要回到子仓库

`zgi-pre` 负责“组装和启动”。

如果你要改具体服务行为，通常应该回到对应仓库：

- 后端逻辑改 `api/`
- 前端改 `web/`
- 沙箱运行逻辑改 `sandbox/`
- 插件执行逻辑改 `plugin-runner/`

如果改了子仓库，常见流程是：

1. 先在子仓库提交
2. 再在 `zgi-pre` 提交更新后的 submodule 指针
