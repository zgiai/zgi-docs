# 常见问题

## 为什么需要递归克隆？

`zgi-pre` 通过子模块引用多个服务仓库。递归克隆可以一次性拉取顶层仓库和所有子模块，避免启动时缺少服务代码。

## 已经克隆过仓库怎么办？

在仓库根目录执行：

```bash
git submodule update --init --recursive
```

## 本地端口冲突怎么办？

可以修改 `docker/.env` 中对应的宿主机端口，然后重新启动本地 Docker 栈。

## 修改服务代码应该提交到哪里？

如果是具体服务行为，应先提交到对应子仓库，例如 `api/` 或 `web/`。随后再回到 `zgi-pre` 提交更新后的子模块指针。

## 知识库回答不准确怎么办？

优先检查文档是否过期、标题是否清晰、切片是否合理、召回内容是否相关。必要时调整知识库结构和检索参数。
