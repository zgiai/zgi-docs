# 常见问题

## ZGI 和直接调用模型 API 有什么区别？

直接调用模型 API 只能获得单次推理能力。ZGI 提供的是平台层能力，包括知识库管理、多模型接入、可视化工作流、权限成本管控、应用发布、审计日志和运维治理。

## 知识库回答的准确性如何保证？

ZGI 不让模型单纯“猜答案”，而是先从知识库检索相关原文，再将上下文交给模型生成回答。回答中应附带文档、页码、段落等引用信息，便于业务人员核验。如果知识库没有相关内容，应明确提示，而不是编造。

## 数据会上传到 ZGI 服务器吗？

云端 SaaS 版本下，资料会进入云端存储和处理链路。对数据安全要求严格的企业可以选择私有化部署，让文档解析、OCR、知识库、数据库和模型调用在企业内网完成。

## 支持本地开源大模型吗？

支持。模型网关可以接入 Ollama 兼容的本地模型，也可以接入企业自建模型服务。私有化部署场景下，可以构建不依赖外部模型 API 的应用链路。

## 如何选择部署方式？

- 快速验证或中小团队：优先云端 SaaS。
- 数据不能出内网：选择私有化部署。
- 跨区域或大型组织：评估混合架构。

## ZGI 是开源的吗？

ZGI 核心框架在 GitHub 开源。企业版通常会提供私有化部署、专属支持和合规相关能力。

## 如何开始试用？

可以从云端工作区开始，先跑通知识库和工作流。如果需要私有化部署，应先确认部署规模、模型来源、数据安全要求和集成系统清单。

## 本地端口冲突怎么办？

修改本地 `.env` 中的 `HOST_*_PORT` 变量后重新启动服务。例如将 PostgreSQL 端口从 `15432` 改为其他未占用端口。
