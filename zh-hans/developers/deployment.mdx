# 部署指南

ZGI 可以按业务阶段和安全要求选择不同部署方式：云端 SaaS、私有化部署、混合架构或开源版本地启动。

## 部署方式对比

| 维度 | 云端 SaaS | 私有化部署 | 混合架构 |
| --- | --- | --- | --- |
| 数据位置 | ZGI 云端 | 企业内网 | 核心数据内网，部分计算云端 |
| 上线时间 | 即开即用 | 需要企业 IT 配合 | 需要架构设计 |
| 运维成本 | 低 | 中到高 | 中 |
| 合规控制 | 平台统一提供 | 企业完全自控 | 按数据类型分级 |
| 适合场景 | 快速验证、中小团队 | 金融、政务、医疗等敏感场景 | 跨区域或大型企业 |

## 私有化部署准备

私有化部署通常需要提前确认 License、安装包、数据库、对象存储、模型来源和网络策略。

最低环境建议：

| 组件 | 建议 |
| --- | --- |
| 操作系统 | Linux，例如 Ubuntu 20.04+ 或 CentOS 7+ |
| CPU | 8 核起步，生产建议 16 核以上 |
| 内存 | 16 GB 起步，生产建议 32 GB 以上 |
| 存储 | SSD，按知识库规模规划 |
| 运行时 | Docker 20.10+ 或 Kubernetes 1.24+ |
| 数据库 | PostgreSQL 14+、Redis 6+ |

## 开源版本地启动

开源版采用多仓库和子模块组织。顶层仓库负责聚合服务、生成 Compose 配置和启动本地环境。

```bash
git clone --recurse-submodules https://github.com/zgiai/zgi.git
cd zgi
make dev-docker
```

首次运行会自动完成子模块初始化、环境变量模板补齐、Compose 文件生成和服务启动。

## 中国大陆网络加速

如果镜像构建较慢，可以使用中国大陆网络模式：

```bash
./dev/start-docker --china
```

该模式只影响本次构建配置，不应永久改写仓库中的默认模板。

## 环境变量管理

```bash
make env-check
make env-sync
```

`env-check` 用于检查本地环境变量和模板差异，`env-sync` 用于追加缺失项而不覆盖已有值。

## 源码开发模式

如果后端和前端希望直接用源码运行，可以让数据库、缓存等中间件继续通过 Docker 提供。

```bash
make setup
make dev-docker
make dev-api
make dev-web
```

## Kubernetes 部署

生产高可用场景建议使用 Kubernetes，并结合 Helm Chart、持久化存储、日志采集、监控告警和密钥管理统一规划。

```bash
helm repo add zgi https://charts.zgi.cn

helm install zgi zgi/zgi \
  --namespace zgi --create-namespace \
  --set global.storageClass=your-storage-class \
  --values values-production.yaml
```
