# 知识库 & RAG

ZGI 知识库负责把企业文档、表格、图片和压缩包中的资料转化为可检索、可引用、可被智能体使用的知识。它的目标不是让模型凭空回答，而是让回答尽量基于企业自己的原始材料。

## 支持的资料类型

| 类型 | 常见格式 | 处理能力 |
| --- | --- | --- |
| 文档 | PDF、Word、TXT、Markdown | 支持正文解析、语义切分和原文引用 |
| 表格 | Excel、CSV | 支持结构化字段识别和后续查询 |
| 图片 | PNG、JPG、TIFF | 支持图文内容识别，适合扫描件和截图 |
| 批量导入 | ZIP | 可按目录批量组织资料 |

## 文档处理流程

1. 判断文档类型和版式。
2. 提取文字、表格、图片和关键元数据。
3. 按语义边界切分内容片段。
4. 生成向量索引，并同步保留原文定位信息。
5. 对候选片段进行相关性排序。
6. 将召回内容交给模型生成回答，并返回引用来源。

## 多路混合召回

ZGI 不只依赖单一向量检索，而是组合多种召回方式：

- **向量检索**：适合语义相近但表述不同的问题。
- **关键词检索**：适合合同编号、金额、日期、条款名称等精确字段。
- **知识图谱召回**：适合实体关系、关联方、项目归属等关联型问题。
- **重排序**：融合多路结果后重新打分，提升最终上下文质量。

## 引用溯源

知识库回答应返回引用信息，包括文档名、页码、段落或片段位置。对法务、财务和合规场景来说，引用比单纯答案更重要，因为业务人员需要快速核验来源。

```json
{
  "answer": "根据合同第五条，付款期限为 30 个自然日。",
  "citations": [
    {
      "source": "服务协议_20250101.pdf",
      "page": 4,
      "paragraph": "第五条 付款条件..."
    }
  ]
}
```

## API 能力

常见知识库接口包括：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/v1/knowledge-bases` | 创建知识库 |
| `POST` | `/v1/knowledge-bases/{id}/documents` | 上传文档 |
| `POST` | `/v1/knowledge-bases/{id}/query` | 查询知识库并返回引用 |
| `GET` | `/v1/knowledge-bases/{id}/documents` | 列出文档 |
| `DELETE` | `/v1/knowledge-bases/{id}/documents/{doc_id}` | 删除文档 |

## 使用建议

- 首次导入少量高质量资料，先验证召回质量。
- 资料标题、目录和版本要清晰，避免相同主题的过期资料混在一起。
- 对合同、制度、产品手册等资料，建议保留原始页码和章节结构。
- 对高风险业务场景，应要求回答必须带引用。
