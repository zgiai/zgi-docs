智能体编排用于把模型推理、知识召回、数据库查询、代码执行、外部 API 和人工确认组织成可执行流程。它让 AI 不只是“回答一句话”，而是可以按步骤完成业务任务。

## 核心概念

| 概念 | 说明 |
| --- | --- |
| 节点 | 工作流中的基本执行单元，例如模型推理、知识召回、HTTP 请求或代码执行 |
| 工作流 | 由节点和连线组成的有向流程，定义任务执行顺序和分支逻辑 |
| 智能体 | 具备上下文判断能力的流程单元，可以根据输入决定调用哪些能力 |
| 触发器 | 启动流程的方式，例如用户消息、Webhook、定时任务或 API 调用 |

## 常见节点类型

- LLM 节点：调用大模型完成生成、分析、翻译、总结等任务
- 知识召回节点：从指定知识库检索上下文，并保留原文引用
- NL2SQL 节点：把自然语言转换成 SQL，查询企业数据库
- 条件分支节点：根据变量值选择执行路径
- HTTP 请求节点：调用 OA、ERP、工单系统或内部服务
- 代码执行节点：运行自定义脚本处理数据
- 循环节点：对列表或多条记录批量处理
- 输出节点：返回结果、写入数据库或发送通知

## 示例：合同审核流程

1. 用户上传合同文件。
2. 文档解析节点提取合同正文、表格和关键信息。
3. 知识召回节点从法规库和公司制度中检索相关条款。
4. 模型节点识别风险点并生成审核意见。
5. 条件分支判断风险等级。
6. 高风险合同自动通知法务，低风险合同直接返回审核报告。

## 设计建议

- 把复杂任务拆成多个可观察节点，便于调试和审计。
- 对高风险流程加入人工确认节点。
- 把外部 API 调用单独封装，避免把业务系统细节写入提示词。
- 重要输出应结构化，方便后续写入数据库或继续流转。
