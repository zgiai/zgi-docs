工作流用于把 AI 任务拆成可编辑、可调试、可发布的步骤。业务人员可以通过画布编排节点，开发者可以通过 API 或 Webhook 把流程接入业务系统。

## 创建流程

### 1. 新建工作流

在工作流页面选择模板，或从空白画布开始。常见模板包括合同审核、制度问答、数据分析和文档处理。

### 2. 添加节点

从左侧面板拖入模型、知识库、数据库、HTTP 请求、条件分支、循环、人工确认和输出节点。每个节点都应配置输入、输出和失败处理策略。

### 3. 连接节点

使用连线定义执行顺序。需要分支时，可以在连线上设置条件表达式，例如风险等级、分类结果或字段是否为空。

### 4. 调试运行

输入测试数据，查看每个节点的入参、出参、执行时间和错误信息。调试阶段应重点检查知识库召回是否准确、模型输出是否稳定、外部接口是否可用。

### 5. 发布

调试通过后，可以发布为对话应用、Web Chat、API 端点或 Webhook 流程。

## 触发方式

| 触发方式 | 说明 | 典型场景 |
| --- | --- | --- |
| 用户消息 | 用户在对话界面输入后触发 | 问答机器人、内部助手 |
| Webhook | 外部系统通过 HTTP 调用触发 | OA 审批、工单事件 |
| 定时任务 | 按 Cron 表达式定时执行 | 日报、周报、周期性分析 |
| API 调用 | 开发者主动触发 | 集成到自研系统 |
| 文件上传 | 上传文件后自动执行 | 合同审核、发票录入 |

## 适合用工作流的任务

- 多步骤处理，并且步骤顺序相对稳定。
- 需要把模型和业务系统连接起来。
- 需要记录每一步输入输出，方便审计。
- 需要人工确认、条件分支或批量循环。

如果任务高度开放、需要自主规划，可以把工作流与智能体结合使用：工作流负责主路径，智能体负责局部判断和生成。
